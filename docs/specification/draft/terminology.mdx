## Requirement levels

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT",
"RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as
described in [BCP 14](https://www.rfc-editor.org/info/bcp14)
([RFC 2119](https://www.rfc-editor.org/rfc/rfc2119),
[RFC 8174](https://www.rfc-editor.org/rfc/rfc8174)) when, and only when, they appear in all
capitals, as shown here.

A rule written in lowercase prose is explanatory and carries no requirement of its own.

## Terms

**Factory** — a single SFML document: the declarative description of a pipeline.

**Run** — one execution of a factory, identified by a run id minted by the implementation.

**Step** — a named node in the factory graph. One of `agent`, `human`, `parallel`, or `result`.

**Connection** — one edge out of a step, with an optional `when` condition and exactly one target.
Every connection is a success edge.

**Region** — the set of child steps declared by a `parallel` step. A region has a single entry and a
single exit, and contains no edges.

**Branch** — one live thread of control within a run. A run has one branch, except while inside a
`parallel` step, where it has one per child.

**Harness** — the runtime that actually executes an `agent` step. SFML names it and passes it
`harness_config`; everything beyond that is the harness's own business.

**Factory state** — the `parameters` a run was started with and the `results` each step has
produced. It is what routing conditions, human `instructions`, and result `value`s are evaluated
against.

**Step result** — the validated result object a step produces on success. A failed attempt produces
nothing.

**Admission** — the stage at which a run is accepted or rejected, before a run id exists and before
anything has run. Distinct from linting, which has no identity system and no caller-supplied values
to check.

**Implementation** — any software that reads SFML documents and executes runs of them. A
**conforming** implementation is one that satisfies every MUST in this specification and documents
the choices this specification requires it to document.
